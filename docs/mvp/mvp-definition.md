# Atlas MVP Definition v1

## Estado del documento

Documento oficial de preparación final para construir Atlas MVP v1 en Lovable. No contiene código ni autoriza implementación hasta que exista ADR de inicio.

## Objetivo del MVP v1

Construir una primera versión de Atlas que permita visualizar, organizar y dar seguimiento a la especificación oficial del proyecto desde una interfaz clara.

## Propuesta de valor MVP

Atlas MVP v1 debe convertir la documentación oficial en una experiencia navegable para entender estado, decisiones, backlog, roadmap, readiness y recursos.

## Usuarios del MVP

- Responsable del proyecto.
- CTO o líder técnico.
- Colaboradores de producto, diseño y documentación.
- Desarrolladores que recibirán el handoff para futuras fases.

## Módulos incluidos

| Módulo | Propósito | Prioridad |
| --- | --- | --- |
| Dashboard | Mostrar estado general y próximos pasos | Alta |
| Documentos | Navegar especificación por dominio | Alta |
| Decisiones | Consultar decisiones y ADRs | Alta |
| Backlog | Ver tareas por prioridad y estado | Alta |
| Roadmap | Mostrar etapas del proyecto | Media |
| Readiness | Ver criterios pendientes para implementación | Alta |
| Recursos | Centralizar enlaces y referencias | Media |

## Módulos fuera de alcance v1

- Automatizaciones con IA.
- Envío real de correos.
- Integraciones externas.
- Gestión avanzada de permisos.
- Editor colaborativo en tiempo real.
- Analítica avanzada.

## User stories iniciales

- Como responsable del proyecto, quiero ver el estado general para saber qué sigue.
- Como CTO, quiero revisar readiness para decidir si se puede implementar.
- Como colaborador, quiero navegar documentos por dominio para encontrar la información correcta.
- Como revisor, quiero consultar decisiones para entender por qué se eligió una dirección.
- Como equipo futuro, quiero ver backlog y roadmap para planear ejecución.

## Criterios de aceptación MVP v1

- El dashboard muestra estado, etapa actual, pendientes críticos y últimas decisiones.
- La documentación está agrupada por dominio.
- Las decisiones muestran fecha, estado, contexto y consecuencia.
- El backlog distingue prioridad y estado.
- El roadmap muestra etapas completas, pendientes y bloqueadas.
- Readiness deja claro qué falta antes de construir nuevas fases.
- La experiencia respeta el Design System.
