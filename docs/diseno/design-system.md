# Design System de Atlas

## Estado del documento

Este documento es parte de la especificación oficial de Atlas. Define bases de identidad, tono, experiencia y diseño sin generar interfaz ni código todavía.

## Principios de diseño

- **Claridad:** cada pantalla, documento o flujo futuro debe ser fácil de entender.
- **Orden:** la información debe agruparse por propósito.
- **Confianza:** el sistema debe comunicar estabilidad y trazabilidad.
- **Progreso:** el usuario debe saber qué está listo, qué falta y qué sigue.
- **Sobriedad:** evitar ruido visual o elementos innecesarios.

## Personalidad de marca

Atlas debe sentirse:

- Claro.
- Profesional.
- Estratégico.
- Confiable.
- Estructurado.

## Tono de voz

- Español claro y directo.
- Frases breves.
- Evitar tecnicismos innecesarios.
- Explicar decisiones con contexto.
- Priorizar instrucciones accionables.

## Lenguaje visual conceptual

| Elemento | Dirección |
| --- | --- |
| Color base | Neutros sobrios |
| Color de acento | Azul o índigo para confianza y dirección |
| Tipografía | Legible, moderna, sin ornamentación excesiva |
| Iconografía | Simple, lineal y funcional |
| Espaciado | Amplio, ordenado y consistente |

## Componentes futuros posibles

- Encabezado de proyecto.
- Tarjetas de estado.
- Lista de decisiones.
- Backlog priorizado.
- Timeline de roadmap.
- Panel de riesgos.
- Vista de recursos.

## Reglas UX futuras

1. Mostrar primero el estado del proyecto.
2. Separar claramente pendientes, decisiones y documentación.
3. Permitir navegación por áreas.
4. Evitar acciones destructivas sin confirmación.
5. Mantener consistencia entre documentación y experiencia visual.

## Fuera de alcance actual

- No se crean pantallas.
- No se definen componentes en código.
- No se generan assets visuales finales.
- No se selecciona framework de UI.
