# MVP User Journey de Atlas

## Estado del documento

Documento oficial para preparar la aprobación del MVP v1 antes de iniciar construcción en Lovable. No contiene código.

## Objetivo

Definir el recorrido principal de usuario para Atlas MVP v1 y asegurar que la experiencia futura esté alineada con Product Bible, UX Specification y Design System.

## Usuario principal

Responsable del proyecto que necesita revisar el estado de Atlas, entender qué está listo, consultar decisiones y confirmar próximos pasos.

## Journey principal

### 1. Entrada al Dashboard

El usuario entra a Atlas y ve:

- Nombre del proyecto.
- Estado actual.
- Etapa del roadmap.
- Próximos pasos.
- Pendientes críticos.
- Últimas decisiones.

**Resultado esperado:** el usuario entiende el estado del proyecto sin navegar primero por documentos largos.

### 2. Revisión de documentación

El usuario abre la biblioteca documental y navega por dominios:

- Producto.
- Arquitectura.
- Diseño.
- Operación.
- Seguridad.
- API e integraciones.
- Roadmap.

**Resultado esperado:** el usuario encuentra rápidamente la fuente de verdad correspondiente.

### 3. Consulta de decisiones

El usuario revisa decisiones y ADRs con:

- Fecha.
- Estado.
- Contexto.
- Decisión.
- Consecuencias.

**Resultado esperado:** el usuario entiende por qué Atlas tomó cierta dirección.

### 4. Revisión de backlog y roadmap

El usuario consulta pendientes priorizados y etapas del roadmap.

**Resultado esperado:** el usuario identifica qué se debe hacer después y qué está bloqueado.

### 5. Validación de readiness

El usuario revisa criterios de readiness por dominio antes de iniciar implementación.

**Resultado esperado:** el usuario sabe si Atlas puede pasar a construcción en Lovable o qué falta aprobar.

## Journey del CTO

1. Revisar Lovable Master Spec.
2. Revisar System Architecture.
3. Revisar Database Schema v1.
4. Revisar Security Model v1.
5. Validar ADR-001.
6. Aprobar o bloquear inicio de implementación.

## Momentos clave

- Primer entendimiento del estado del proyecto.
- Confirmación de documentación oficial.
- Identificación de bloqueos.
- Aprobación formal para iniciar construcción.

## Criterios de éxito UX

- El usuario entiende estado y próximos pasos en menos de un minuto.
- La navegación por dominios es clara.
- Las decisiones son fáciles de auditar.
- Readiness muestra bloqueos sin ambigüedad.
- La experiencia mantiene tono sobrio, claro y profesional.
