# Product Bible de Atlas

## Estado del documento

Este documento es parte de la especificación oficial de Atlas. Define la visión de producto, el problema, los usuarios, el alcance y las reglas de evolución del producto.

## Visión

Atlas es una base documental y operativa para transformar ideas, conversaciones y decisiones en una especificación clara, trazable y lista para evolucionar hacia producto cuando el alcance esté aprobado.

## Principio central

Atlas no empieza escribiendo código. Atlas empieza convirtiendo intención, contexto y decisiones en documentación oficial que pueda ser revisada, versionada y ejecutada por etapas.

## Problema

Los proyectos suelen iniciar con conversaciones dispersas, decisiones no documentadas y expectativas implícitas. Eso provoca retrabajo, pérdida de contexto y decisiones técnicas prematuras.

## Solución propuesta

Atlas centraliza la documentación fundacional del proyecto en GitHub, separando producto, arquitectura, operación, seguridad y diseño para que cada decisión tenga un lugar claro.

## Usuarios principales

- Fundador o responsable del proyecto.
- CTO o líder técnico.
- Colaboradores de producto y documentación.
- Futuros diseñadores o desarrolladores que reciban una especificación lista para ejecutar.

## Promesa de producto

Atlas permite pasar de una idea a una especificación oficial sin perder contexto, manteniendo decisiones, tareas y criterios de implementación en documentos versionados.

## Alcance oficial actual

Incluido:

- Documentación fundacional.
- Especificación de producto.
- Especificación AIOS conceptual.
- Design System documental.
- Gobernanza y criterios de implementación.
- Plantillas para colaboración.

No incluido todavía:

- Código de aplicación.
- UI implementada.
- Infraestructura.
- Integraciones externas.
- Automatizaciones.

## Reglas de producto

1. Todo cambio de alcance debe registrarse en documentación.
2. Toda nueva funcionalidad futura debe partir de un problema validado.
3. No se implementa nada si no existe definición de ready.
4. El README debe seguir siendo una puerta de entrada, no la especificación completa.
5. La Product Bible tiene prioridad sobre documentos exploratorios si existe conflicto.

## Métricas de éxito iniciales

- Cualquier persona puede entender qué es Atlas desde el README y el índice.
- Las decisiones clave están registradas.
- El alcance actual y el fuera de alcance son claros.
- La implementación futura está bloqueada hasta cumplir criterios formales.
- La documentación puede crecer sin romper la estructura actual.
